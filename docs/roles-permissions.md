# Roles and Permissions

## Завідувач відділення

Runtime membership-role: `department_head`.

На першому активованому етапі може:
- переглядати tenant-scoped агреговані оперативні показники;
- бачити агреговане навантаження по обладнанню;
- бачити агреговані стани клінічної черги;
- бачити кількість активних працівників за ролями;
- бачити агреговані показники несправностей, ТО і простоїв;
- переглядати tenant-scoped графік змін персоналу;
- призначати працівникам циклічні графіки/бригади та персональні корекції днів.

Не отримує через management context:
- ПІБ, телефони або картки пацієнтів;
- суми оплат, платіжну історію або фінансові звіти;
- тексти протоколів, ревізії або право підпису;
- DICOM study/series metadata;
- системні секрети, PACS/MWL configuration або керування обліковими записами.

Право керування графіком змін є окремою кадрово-операційною capability: воно дозволяє бачити службові ПІБ/посади активного персоналу свого tenant лише для планування змін і не розширює доступ до пацієнтських або клінічних даних.

Legacy `admin` тимчасово зберігає старий широкий набір прав для backward compatibility. Подальші права завідувача — деталізовані звіти, контроль персоналу та затвердження налаштувань відділення — мають додаватися окремими capability, а не через прирівнювання до `admin`.

## Старший рентгенлаборант

Може:
- відкривати/закривати зміну;
- розподіляти персонал;
- керувати готовністю кабінетів;
- переглядати календар усіх кабінетів;
- контролювати витратні матеріали;
- реєструвати несправності;
- формувати оперативні звіти.

## Лікар-рентгенолог

Може:
- переглядати призначені дослідження;
- створювати й підписувати протоколи;
- використовувати шаблони;
- підтверджувати невідкладне контрастне дослідження;
- переглядати історію пацієнта в межах дозволу;
- переглядати власний графік змін read-only.

## Лікар УЗД

Може:
- керувати власним списком досліджень;
- створювати протоколи УЗД;
- підписувати висновки УЗД.

## Рентгенлаборант

Може:
- переглядати чергу свого кабінету;
- позначати прибуття;
- починати/завершувати дослідження;
- фіксувати повторний знімок;
- повідомляти про несправність;
- переглядати власний графік змін read-only.

Не може підписувати лікарський висновок.

## Медична сестра

Може:
- вести чек-лист контрасту;
- фіксувати катетер;
- вести облік контрасту та витратних матеріалів;
- фіксувати реакції.

## Санітарка

Може:
- бачити графік прибирання;
- відмічати поточне/генеральне прибирання;
- підтверджувати готовність приміщення;
- повідомляти про нестачу деззасобів.

Не має доступу до клінічного протоколу.

## Реєстратор

Може:
- обробляти заявки;
- створювати/редагувати записи;
- бачити календар;
- зв'язуватися з пацієнтом;
- фіксувати оплату;
- створювати картку пацієнта;
- переглядати власний графік змін read-only.

Не може редагувати підписаний протокол.

## Інженер

Може:
- переглядати обладнання;
- реєструвати ремонт і ТО;
- змінювати технічний статус;
- фіксувати простій.

Доступ до медичних даних мінімальний.

## Системний адміністратор

Runtime membership-role: `organization_admin`.

Може:
- керувати користувачами та tenant-ролями;
- налаштовувати системні інтеграції;
- керувати PACS/MWL configuration;
- переглядати system/integration health;
- переглядати власний графік змін через neutral self-service context.

Не має medical/operational tenant context і тому не повинен отримувати через staff API:
- заявки та картки пацієнтів;
- клінічні протоколи та їх зміст;
- DICOM-дослідження/серії;
- реєстр пацієнтів або clinical search;
- право керувати графіками змін інших працівників.

Legacy `admin` тимчасово зберігає старий широкий набір прав для backward compatibility. Перехід існуючих акаунтів на окремі `organization_admin` / медичні ролі має виконуватися окремою контрольованою міграцією, а не автоматичним backfill.
