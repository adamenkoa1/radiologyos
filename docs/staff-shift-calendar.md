# Графік змін персоналу

## Призначення

`/staff/shifts` — tenant-scoped кадрово-операційний планувальник персоналу. Це не господарський документ і не клінічний об'єкт: він не створює проводок, регістрів, медичних записів або фінансових фактів.

Модуль відтворює корисну логіку старої Windows-програми Calendar6 у сучасному Web MVP RadiologyOS:

```text
тип графіка
→ бригада / фаза
→ повторювана матриця днів
→ опорна дата
→ персональна корекція конкретного дня
```

## Джерело Calendar6

Вихідний архів містив `Setting.mdb`, але файл фактично є текстовим INI у Windows-1251, а не Microsoft Access database. Старий EXE для відновлення логіки запускати не потрібно.

У конкретному наданому `Setting.mdb` описано 8 типів графіків:

1. `День-ночь-трое дома` — 5-денний цикл, 5 бригад, день 08:00–20:00, ніч 20:00–08:00.
2. `Два дня через два` — 4-денний цикл, 2 бригади.
3. `Сутки-трое` — 4-денний цикл, 4 бригади.
4. `День-ночь-48` — 4-денний цикл, 4 бригади, день 08:00–20:00, ніч 20:00–08:00.
5. `4 в день 2 отдых` — у source заявлено 6 бригад, але реально заповнено лише 2 матриці; RadiologyOS переносить тільки фактично задані дані й показує попередження замість домислювання відсутніх фаз.
6. `Три смены в сутки` — 16-денний цикл, 4 бригади; зміни 07:30–15:29, 15:30–23:59, 00:00–07:29.
7. `2день-2ночь-3дома` — 21-денна матриця, 3 бригади.
8. `2День-2В-2Ночь-2В` — 8-денний цикл, 4 бригади.

Демонстраційні ПІБ/дати народження зі старого INI не імпортуються. Працівники беруться лише з актуального tenant-scoped довідника `memberships + staff_members`.

## Опорна дата

У старому INI немає надійної канонічної опорної дати, від якої можна безпечно відновити реальну історичну фазу для сучасного персоналу. Тому RadiologyOS не вгадує її.

Керівник явно задає:

- тип графіка;
- номер бригади;
- опорну дату.

На опорну дату використовується перший елемент матриці обраної бригади. Далі engine циклічно повторює матрицю вперед і назад календарними днями.

## Персональні корекції

Для конкретної дати можна замінити базовий цикл на:

- денну;
- вечірню;
- нічну;
- добове чергування;
- робочу зміну;
- вихідний;
- відсипний;
- відпустку;
- лікарняний;
- довільну позначку.

Корекція може містити час і коротку службову примітку. У примітках не слід зберігати медичні дані.

Видалення корекції повертає день до розрахованого циклу — сам базовий графік не переписується.

## D1

### `staff_shift_assignments`

Одна актуальна циклічна схема на працівника в tenant:

```text
organization_id + staff_email
preset_code
team_index
anchor_date
created_by / updated_by
created_at / updated_at
```

Composite FK фізично не дозволяє посилатися на membership іншої організації.

### `staff_shift_overrides`

Один ручний виняток на працівника/дату:

```text
organization_id + staff_email + shift_date
kind
label
start_time / end_time
note
created_by / updated_by
created_at / updated_at
```

Override має composite FK на `staff_shift_assignments`, тому не може існувати без базового графіка цього самого tenant+staff.

## RBAC

- `admin` — перегляд і керування всіма графіками свого tenant для backward compatibility.
- `department_head` — перегляд і керування графіками персоналу свого tenant як окрема кадрово-операційна capability.
- `radiologist`, `radiographer`, `registrar` — read-only власного графіка.
- `organization_admin` — read-only власного графіка через self-service context; не отримує право керування персоналом через control-plane роль.

Cross-tenant target завжди fail-closed.

## Audit

Логуються:

- перегляд календаря (`organization` або `self` scope);
- збереження/видалення базового графіка;
- збереження/видалення персональної корекції.

Audit не містить медичних даних.

## UI / експорт

Екран містить:

- навігацію по місяцях;
- таблицю `працівник × день`;
- легенду типів змін;
- редактор циклу та бригади;
- редактор персональної корекції;
- виділення ручних винятків;
- CSV експорт UTF-8 з `;` як роздільником;
- браузерний друк поточного плану.

Друк графіка є поточним operational view, а не immutable historical business printed form, оскільки графік змін не є проведеним господарським документом.
