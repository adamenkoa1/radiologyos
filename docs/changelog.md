### Security

- **`sharp` (під `next`) закріплено на `0.35.5`** — закрито HIGH-вразливість у залежності `librsvg` (CVE-2026-96889, GHSA-wq5f-xc86-pv6w, зачеплені `sharp < 0.35.5`). Прод-шлях — `next → sharp`; CI-гейт `npm audit --omit=dev --audit-level=high` почав падати на цій новорозкритій advisory, знову блокуючи всі PR. Оновлено наявний nested-override `next.sharp` `0.35.4 → 0.35.5`; після бампу `audit --audit-level=high` — чистий. Верхньорівневий `sharp` лишається dev-залежністю (поза `--omit=dev`). Лише lock + `overrides`; код не змінено.
- **`source-map-js` закріплено на `1.2.2`** (через `overrides`) — закрито HIGH-вразливість event-loop DoS через індексовані offset-и секцій source-map (GHSA-68fv-2mgg-jv7q, зачеплені 1.0.0–1.2.1). Пакет приходить транзитивно (`next` → `postcss@8.5.25` → `source-map-js`); CI-гейт `npm audit --omit=dev --audit-level=high` почав падати на цій новорозкритій advisory, знову блокуючи всі PR. `1.2.2` задовольняє `postcss ^1.0.0`, тож бамп безпечний; після нього `audit --audit-level=high` — чистий (лишилась одна moderate `baseline-browser-mapping`, нижче гейту). Лише lock-файл + `overrides`; код не змінено.
- **Next.js `16.3.5` → `16.3.8`** — закрито критичну вразливість RCE у `next/og` `ImageResponse` (GHSA-vcvr-r3jv-pc5j, зачеплені 16.2.0–16.3.5). CI-гейт `npm audit --omit=dev --audit-level=high` (у `ci.yml` і `deploy.yml`) почав падати на цій новорозкритій advisory, блокуючи всі PR. Проєкт не використовує `next/og`/`ImageResponse`, тож RCE недосяжний, але прод-залежність усе одно оновлено до пропатченої версії в межах того ж мінора. `vinext` (Vite-фреймворк) не залежить від `next`, тож бамп безпечний; оновлено лише `next` у lock-файлі, збірка/тести без змін.

### Added

- **Звіт TAT (turnaround time)** (`/staff/reports/turnaround`) — стандартний RIS-показник, якого бракувало: час від виконання дослідження до готового, підписаного й виданого протоколу. Рахується з наявних дат (`bookings.performed_at`/`protocol_ready_at`/`protocol_issued_at` + `protocols.signed_at`), **не з ручних агрегатів** (за правилом business-core). Показує медіану й середнє «до підпису» та «до видачі» загалом, розбивку за модальністю та за лікарем-рентгенологом (хто підписав). Період за замовчуванням — 30 днів; доступ — адміністратор/завідувач (`requireManagementOrgContext`), агрегат без клінічного тексту. Логіка — у `lib/turnaround.ts` (чисті функції) з юніт-тестом; додано лінк у хабі звітів. Ідея — з порівняння з RIS-аналогами.
- **Журнальний скін Google Sheets / Excel розкочено на всі реальні журнали.** Спільна таблиця журналів `.financeTable`/`.financeTableWrap` (документи, фінанси, склад, регістри, персонал, звіти, контрагенти, довідники — 50+ таблиць на 30 сторінках) отримала централізоване табличне оформлення (`app/styles/30-journal-sheet.css`, імпортується останнім): вертикальні лінії комірок, заморожена шапка при прокрутці, зебра рядків, hover-підсвітка, моно-цифри з вирівнюванням праворуч. Скін **additive** й тем-залежний (кольори з `--ws-*` + локальних `--js-*`), тож світла й темна теми працюють без додаткового коду; наявна семантика (`.num.positive`/`.num.negative`, підзаголовки) збережена; друк не отримує внутрішнього скролу/плаваючої шапки. Жодних змін markup сторінок — усі таблиці успадкували скін через спільний клас. Референс — прототип `/staff/sheet-preview`.
- **Прототип оформлення журналів у стилі Google Sheets / Excel** (`/staff/sheet-preview`) — ізольований макет для узгодження табличного вигляду перед розкочуванням на спільний `DataTable`/`JournalForm`. Демонструє літери стовпців, заморожену шапку й номерний гутер, лінії комірок, зебру, виділення рядка кліком, сортування по заголовку, чипи статусу/оплати, моно-цифри з вирівнюванням праворуч, статус-бар із сумою, компакт/комфорт-щільність і темну тему. Дані **умовні** (не реальні пацієнти), жоден API не викликається, стилі інлайнові (не чіпають глобальний CSS). Не робоча сторінка; `noindex,nofollow` успадковано з `app/staff/layout.tsx`.
- **PoC (спайк) переходу з D1/SQLite на PostgreSQL** — ізольований, не підключений до жодного наявного запиту й не змінює рантайм. `lib/db-adapter.ts` вводить тонкий спільний інтерфейс `SqlDatabase` (`all`/`first`/`run` з плейсхолдерами «?»), який реалізують обидва рушії: `d1Adapter` (обгортка над наявним D1 API, запити переносяться дослівно) та `pgAdapter` (той самий інтерфейс поверх будь-якого Postgres-клієнта — `pg`/`postgres.js`/Hyperdrive — без нової рантайм-залежності; транслює «?»→«$1..$n», додає `RETURNING id` замість `last_row_id`). Тест `tests/postgres-poc.test.mjs` перевіряє D1-адаптер на реальному SQLite і PG-адаптер на фейковому клієнті. Висновок і заміри зчеплення (685 викликів `.prepare()` у 119 файлах, 121 міграція, розбіжності діалектів) — у `docs/postgres-poc.md`. Мета — оцінити реальність поступової міграції; за AGENTS.md PostgreSQL лишається **наступним етапом**.
- Друкована кадрова картка (`/staff/personnel/print?id=<personnelId>`): версійований, SHA-256-стемпований, **immutable** snapshot у окремій таблиці `personnel_card_snapshots` (рядковий `personnel_id`, без FK на `business_documents` — кадрова картка не є господарським фактом). Payload самодостатній (усі значення, не лише id), тож форма відтворювана з конкретного snapshot навіть після зміни картки; однаковий рендер згортається в один рядок, зміна даних дає новий snapshot, а тригери `no-update`/`no-delete` захищають історію. Друк — A4 браузером (Save as PDF); права — admin/department_head; кнопка «Друк картки» в редакторі працівника (міграція `0121`).
- Кадрові довідники посад і звань: захардкоджені в клієнті списки `POSITIONS`/`RANKS` винесено в tenant-scoped таблиці `personnel_positions` / `personnel_ranks` (міграція `0120`, org-1 засіяно поточними значеннями). Нова сторінка `/staff/directories/personnel-refs` дозволяє адміністратору/керівнику підрозділу додавати, перейменовувати та приховувати значення без деплою; форма працівника живить datalist-підказки з API (`/api/staff/personnel/directories`) з fallback на дефолти, а поля лишаються free-text, тож уже збережені картки не ламаються. Приховане значення не пропонується для нових карток, але історію не змінює.
- Побічно виправлено латентну неконсистентність ланцюга Drizzle-snapshot (0119 помилково перевикористовував `id` 0114 після ребейзу #460) — вона проявилась би на будь-якій наступній міграції; тепер ланцюг коректний і guard-генерація чиста.

### Added

- **Необов'язкова онлайн-оплата з кошика «Моя заявка»** (публічний сайт): за запитом користувача — хто хоче, може сплатити наперед прямо з панелі заявки. Для платних (цивільних) послуг (сума > 0) у кошику з'являється блок з кнопкою **«💳 Оплатити онлайн»** (відкриває налаштоване посилання оплати `GET /api/pay-link`) + орієнтовна сума й призначення платежу з копіюванням для переказу. Модель **не змінено**: повідомлення «оплата — після проведення дослідження» лишається, оплата подається явно як необов'язкова, остаточну суму підтверджує реєстратура. Це лише посилання/зручність — **не створює господарський факт** (за AGENTS.md публічний платіж входить у business-core лише через trusted confirmation). Призначення/суму вставлено через `textContent` (без HTML-інтерполяції). Тест у `site-bridge`; CSS `.cart-pay*`.
- **Спільний хук мутацій `useSubmit`** (`app/hooks/use-submit.ts`) — за підсумком аудиту стійкості `/staff` (7 сторінок з ідентичним класом дефекту). Хук за побудовою закриває три режими збою, які повторювалися в рукописних submit-хендлерах: **подвійний сабміт** (синхронний re-entry guard через `ref`), **мовчазний збій** (throw маршрутизується в `onError`, а не ковтається `void handler()`), **«залиплий» `busy`** (завжди скидається у `finally`). `run(fn)` виконує `fn` не більше ніж один раз одночасно; повідомлення про успіх/валідацію лишаються в `fn`, непередбачений throw — в `onError`. Як референс на нього переведено `/staff/cash-accounts` (рукописний `try/catch/finally` + локальний `busy` замінено на `const {busy,run}=useSubmit(...)`); поведінка ідентична, boilerplate менше. Решту форм можна мігрувати поступово. Юніт-тест `use-submit-hook`.

### Changed

Поведінка ідентична; тести оновлено під хук.
- Довідники `/staff/counterparties` і `/staff/warehouses` переведено на спільний хук `useSubmit` (продовження адопції після `cash-accounts`): рукописний `busy` + `try/catch/finally` у `save` замінено на `const {busy,run}=useSubmit(onError)` та `await run(async()=>{…})`. Поведінка ідентична (кнопки `disabled={busy}`, той самий `⚠`-notice на збій, best-effort reload, ARIA-ролі), менше дубльованого boilerplate; стійкість гарантує хук за побудовою. Тести оновлено під хук.
