# RadiologyOS Workflows

## 1. Цивільний пацієнт

```text
Публічний сайт
→ вибір послуги
→ заявка
→ CRM
→ перевірка реєстратором
→ дзвінок/повідомлення
→ підтвердження дати й вартості
→ запис у календар
→ оплата
→ прибуття
→ дослідження
→ протокол
→ видача результату
```

## 2. Військовослужбовець

```text
Направлення
→ реєстратура
→ перевірка маршруту
→ черга/запис
→ дослідження
→ опис лікарем
→ результат у МІС або паперово
```

Екстрені дослідження виконуються поза плановою чергою.

## 3. КТ із контрастуванням

```text
Запис
→ визначення показань
→ аналіз креатиніну
→ перевірка креатиніну
→ встановлення катетера 18G/20G
→ перевірка алергії і ризиків
→ прибуття за 15 хвилин
→ підтвердження готовності
→ дослідження
→ спостереження
→ завершення
```

Якщо дані відсутні:
- планове дослідження не починати;
- у невідкладному випадку потрібне рішення лікаря-рентгенолога.

## 4. Робочий день

### Початок зміни

- старший рентгенлаборант відкриває зміну;
- персонал підтверджує присутність;
- кабінети проходять чек-лист;
- санітарка підтверджує готовність;
- несправності фіксуються.

### Протягом дня

- реєстратор керує записами;
- лаборант виконує дослідження;
- медсестра супроводжує контраст;
- лікар описує;
- старший контролює черги.

### Кінець зміни

- незавершені дослідження;
- простої;
- несправності;
- витратні матеріали;
- передача зміни;
- автоматичний звіт.

## 5. Статуси заявки

```text
new
→ progress
→ booked
→ arrived
→ in_progress
→ done
```

Альтернативні:
- cancelled;
- no_show.

## 6. Статуси протоколу

```text
not_started
→ draft
→ ready_for_review
→ signed
→ delivered
```

## 7. Автоматична прив'язка DICOM/PACS

```text
заявка/виконане дослідження
→ Accession Number
→ QIDO-RS пошук
→ рівно один точний збіг Accession
→ валідний StudyInstanceUID
→ збіг модальності з очікуваною для заявки
→ збіг Study Date з датою виконання (або плановою датою, якщо виконання ще не зафіксоване)
→ автоматична прив'язка
```

Якщо QIDO не повернув модальність/дату або вони не збігаються, автоматичну прив'язку не виконувати. Подія відмови фіксується без UID/ПІБ/телефону; персонал може виконати ручну перевірку й прив'язку через захищений staff-інтерфейс.
