# RadiologyOS SEO Rules

## Область застосування

SEO використовується лише для публічних сторінок.

Не індексувати:

- `/staff`;
- `/cabinet`;
- внутрішні маршрути;
- сторінки з персональними даними;
- службові сторінки;
- тестові сторінки.

## Технічні вимоги

Кожна публічна сторінка повинна мати:

- унікальний `<title>`;
- унікальний meta description;
- canonical;
- Open Graph;
- favicon;
- `lang="uk"`;
- коректну ієрархію H1–H3;
- sitemap;
- robots.txt.

## URL

Перевага коротким зрозумілим URL:

```text
/site/
/site/about/
/site/military/
/site/prices/
/site/ct/
/site/xray/
/site/fluorography/
/site/pantomography/
```

## Локальне SEO

Ключові сутності:

- Чернігів.
- Чернігівський військовий госпіталь.
- Відділення променевої діагностики.
- КТ у Чернігові.
- Рентген у Чернігові.
- Флюорографія у Чернігові.
- Пантомографія у Чернігові.

Не перевантажувати сторінки ключовими словами.

## Медичний контент

- Автор/відповідальний лікар.
- Дата оновлення.
- Джерела для медичних рекомендацій.
- Чітке розмежування інформації та медичної консультації.
- Не обіцяти діагноз або результат.

## Schema.org

Реалізовано:

- `MedicalClinic` + `FAQPage` — головна (`public/site/index.html`) і компонент
  `PublicLocalSeo` (NAP із єдиного профілю `lib/public-profile`).
- `MedicalWebPage` + `BreadcrumbList` + `MedicalProcedure` — медичні сторінки
  послуг (КТ / рентген / флюорографія) через компонент `MedicalPageSchema`,
  граф будує `lib/structured-data` (мова `uk`, `lastReviewed`, прив'язка до
  клініки за `@id`).

Джерело істини — генератори в `lib/structured-data.ts`; валідатор
`validateJsonLd` перевіряє обов'язкові поля, а тести
(`tests/structured-data.test.mjs`) — що кожна реальна сторінка дає валідний граф.
NAP і назви беруться з фактичних даних, а не хардкодяться на сторінках.

## Внутрішня перелінковка

- Головна (`public/site/index.html`), секція «Які дослідження проводимо»,
  лінкує модальності на посадкові сторінки послуг, щоб ті не лишалися
  orphan-сторінками (тільки в sitemap, без вхідних посилань):
  флюорографія → `/fluorography`, цифровий рентген → `/xray`,
  КТ → `/ct`, КТ з контрастуванням → `/ct/contrast`.
- Посилання ведуть на канонічну форму **без хвостового слеша** — Next віддає
  її з кодом 200, тоді як форма з `/` (`/ct/`) робить 308-редирект.
- Рентгенографія з барієм лишається текстом: окремої посадкової сторінки
  для неї немає, тому посилання не створюємо (не вигадуємо сторінок під
  послуги без наявного контенту).
- Взаємні посилання: `price.html` і `military.html` мають блок
  «Докладніше про дослідження» (спільний компонент `.service-links`) з
  посиланнями на ті ж посадкові сторінки. Посадкові сторінки вже ведуть на
  прайс/запис, тож перелінковка двобічна.
- Видимі «хлібні крихти»: посадкові сторінки послуг мають семантичний
  `<nav aria-label="Хлібні крихти">` (Головна → КТ → сторінка), що збігається
  з BreadcrumbList-схемою через спільний хелпер `breadcrumbTrail`
  (`lib/structured-data.ts`). Посилання — non-slash форма.

## Відомі напрями для покращення

- `app/sitemap.ts` і canonical у метаданих посадкових сторінок використовують
  URL із хвостовим слешем (`/ct/`), який на проді 308-редиректить на `/ct`.
  Варто узгодити sitemap/canonical із канонічною non-slash формою (або
  ввімкнути `trailingSlash` у конфігурації), щоб прибрати редирект-хоп.
