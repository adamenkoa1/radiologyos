# RadiologyOS Component Library

## Загальні

### AppSidebar
Ліва навігація внутрішньої системи.

Стани:
- expanded;
- collapsed;
- active item;
- section expanded/collapsed.

### AppHeader
Містить:
- назву закладу;
- назву відділення;
- годинник;
- онлайн-статус;
- тему;
- профіль користувача.

### PageHeader
Назва сторінки, опис і основна дія.

### Card
Базовий контейнер для інформації.

### StatCard
Показник, значення, допоміжний текст і тренд.

### Button
Варіанти:
- primary;
- secondary;
- ghost;
- danger;
- icon.

### StatusBadge
Підтримувані статуси:
- new;
- progress;
- booked;
- arrived;
- in_progress;
- done;
- cancelled;
- no_show.

Для господарських документів окремо використовуються стани:
- draft;
- posted;
- reversed;
- cancelled.

### Modal
Для створення/редагування коротких сутностей.

### Drawer
Праворуч для детальної картки пацієнта або запису.

### Toast
Типи:
- success;
- warning;
- error;
- info.

### EmptyState
Порожній стан зі зрозумілою наступною дією.

## BAS-подібні стандартні форми внутрішньої системи

### JournalForm
Канонічна форма списку/журналу для довідників і документів.

Містить:
- заголовок і короткий опис;
- пошук;
- швидкі фільтри;
- розширений відбір;
- сортування;
- збережені представлення;
- табличну частину зі sticky header;
- створити;
- відкрити;
- копіювати;
- друк;
- експорт;
- безпечні масові дії;
- пагінацію або cursor navigation.

На планшеті таблиця може переходити в карткове представлення, але набір дій і фільтрів залишається тим самим.

### ReferenceForm
Канонічна форма довідника.

Містить:
- код/ідентифікатор;
- основні реквізити;
- вкладки або групи полів;
- додаткові реквізити;
- вкладення;
- пов'язані документи;
- історію;
- записати/закрити;
- рольові обмеження редагування.

Приклади: пацієнт, послуга, працівник, обладнання, номенклатура, контрагент.

### DocumentForm
Канонічна форма господарського документа.

Верхня частина:
- номер;
- дата/час;
- організація;
- пацієнт/контрагент;
- підстава;
- відповідальний;
- стан.

Табличні частини:
- послуги;
- матеріали;
- виконавці;
- суми/кількість/ціна;
- інші предметні рядки конкретного документа.

Команди:
- `Записати`;
- `Провести`;
- `Провести і закрити`;
- `Друк`;
- `Ще`;
- `Рухи документа`;
- `Історія змін`.

Після `posted` господарські факти форми read-only; виправлення відбувається через коригування/сторно.

### SelectionForm
Компактна BAS-подібна форма вибору пов'язаної сутності.

Містить:
- пошук;
- фільтри;
- нещодавно використані;
- вибрати;
- відкрити картку;
- швидко створити новий запис, якщо роль має право.

### DocumentMovementsView
Read-only перегляд рухів проведеного документа:
- регістр;
- період;
- виміри;
- ресурси;
- документ-реєстратор.

Не показує клінічні дані користувачам без відповідних медичних прав.

### PrintMenu
Єдина команда `Друк` у формах документів.

Містить:
- перелік дозволених друкованих форм для типу документа;
- попередній перегляд;
- створення PDF;
- друк;
- повторний друк історичного snapshot;
- номер версії шаблону;
- інформацію про сформовану версію.

### PrintedFormPreview
Попередній перегляд друкованої форми з контрольованою областю друку.

Обов'язково:
- формат сторінки;
- поля;
- нумерація сторінок для багатосторінкових форм;
- правильні перенос рядків і таблиць;
- відсутність зайвих UI-елементів у print CSS;
- формування з tenant/RBAC перевіркою.

### RegisterReport
Стандартний звіт над регістрами:
- період;
- відбори;
- групування;
- показники;
- drill-down до документа-реєстратора;
- збережений варіант;
- друк/PDF/Excel-експорт за правами.

## Пацієнти і дослідження

### PatientCard
- ПІБ;
- телефон;
- дата народження;
- категорія;
- останнє дослідження.

### StudyCard
- модальність;
- анатомічна ділянка;
- статус;
- дата;
- лікар;
- лаборант.

### ProtocolEditor
- шаблон;
- структуровані поля;
- опис;
- висновок;
- попередній перегляд;
- друк;
- PDF.

`ProtocolEditor` використовує спільну print infrastructure, але підписаний клінічний протокол зберігає окремий append-only revision lifecycle.

## Адміністрування

### DataTable
- пошук;
- фільтри;
- сортування;
- пагінація;
- експорт.

Для нових внутрішніх журналів перевага надається `JournalForm`, що використовує `DataTable` як базовий табличний компонент.

### StaffEditor
ПІБ, телефон, звання, email, посада, роль, графік.

### EquipmentEditor
Кабінет, апарат, тип, статус, характеристики, графік.

### PriceEditor
Група, код, назва, опис, ціна, код НК.

### ReportBuilder
Фільтри, колонки, шаблони, Excel-експорт.

## Правило

Перед створенням нового компонента перевірити, чи можна:
1. використати існуючий;
2. розширити існуючий;
3. використати одну зі стандартних BAS-подібних форм;
4. додати новий лише після цього.
