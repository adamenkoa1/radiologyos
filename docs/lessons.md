# Lessons Learned

## 1. Публічний сайт і внутрішня система — різні контури

Публічний сайт призначений для пацієнтів.
Внутрішня система — для персоналу.
Вони можуть мати спільний дизайн, але різні вимоги до безпеки.

## 2. GitHub Pages не є медичною інформаційною системою

Не зберігати на ньому реальні:

- ПІБ;
- телефони;
- діагнози;
- направлення;
- протоколи;
- DICOM;
- медичні документи.

## 3. Одна заявка — один пацієнт

У заявці може бути кілька досліджень.
Не створювати дублікати пацієнта для кожної послуги.

## 4. Календар організовується за ресурсами

Основні ресурси:

- кабінет;
- апарат;
- модальність;
- персонал.

## 5. Погоджена структура ролей

Є:
- завідувач;
- старший рентгенлаборант;
- лікар-рентгенолог;
- лікар УЗД;
- рентгенлаборант;
- медична сестра;
- санітарка;
- реєстратор;
- інженер;
- системний адміністратор.

Немає ролі «старша медична сестра».

## 6. Пантомографія, не мамографія

Не додавати непогоджені модальності.

## 7. Сервер — другий етап

Етап 1:
- Web MVP;
- HTML/CSS/JS;
- тестові дані;
- UX-перевірка.

Етап 2:
- локальний сервер;
- PostgreSQL;
- API;
- Orthanc;
- DICOM;
- реальна авторизація;
- журнал дій;
- резервні копії.

## 8. Сенсорний інтерфейс не повинен залежати від hover

Кнопки й дії мають бути видимі на планшеті.

## 9. Оплата лише після підтвердження

Оплату доцільно показувати після перевірки запису, дати, послуги й суми реєстратором.

## 10. КТ із контрастом потребує окремого workflow

Обов'язково враховувати:
- креатинін;
- катетер;
- алергію;
- супутні ризики;
- рішення лікаря у невідкладних випадках.

## 11. Внутрішня система — це облікова система клініки, а не набір сторінок

Для господарської частини RadiologyOS базовим референсом є BAS Small Company.

Канонічна модель:

```text
Довідники → Документи → Проведення → Регістри → Звіти
```

Наслідки:
- гроші, борги, залишки, виробіток і завантаження не повинні жити як незалежні вручну редаговані підсумки;
- проведений документ не переписується непомітно — потрібне коригування/сторно;
- внутрішні екрани мають використовувати спільні форми журналу, довідника, документа, вибору та звіту;
- друковані форми є частиною ядра, шаблони версіонуються, а історичний друк має бути відтворюваним;
- медичні модулі (DICOM, протоколи, clinical workflow) накладаються поверх бізнесового ядра та додають суворіші правила доступу й незмінності.
