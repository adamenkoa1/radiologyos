# Імпорт клінічної бібліотеки шаблонів — журнал (MASTER PROMPT 4)

Журнал інтеграції зовнішньої клінічної бібліотеки протоколів у **наявний**
конструктор `/staff/protocols`. Веде фактичний стан і рішення. Канонічні
правила — `AGENTS.md`; план конструктора — `docs/protocols-constructor.md`;
журнал MP3 — `docs/protocol-builder-master-audit.md`.

## Обов'язкові межі (MP4 — не порушувати)

1. Не змінювати механізм підписання.
2. Не змінювати клінічний lifecycle (`draft → ready → signed → issued`).
3. Не перезаписувати персональні шаблони/макроси лікарів.
4. Не змінювати історичні ревізії.
5. Не видаляти наявні каталоги (`lib/protocols.ts`, `lib/findings-composer.ts`).
6. Не підключати зовнішній AI.
7. Не передавати дані пацієнтів назовні.
8. **Не виконувати production-імпорт без окремого дозволу.**
9. Не публікувати клінічно неперевірені шаблони.
10. Не імпортувати приклади синтетичних пацієнтів як реальні записи.

Порядок PR: **PR1 Library Audit** → PR2 Import Adapter → PR3 Builder
Integration → PR4 Clinical Validation. Не створювати паралельний конструктор —
лише розширювати наявний.

## Этап 0 — аудит архіву (PR1, завершено)

Проміжну бібліотеку розпаковано й перевірено **безпосереднім підрахунком**, не
довіряючи маніфесту. Джерело під `clinical-library/` (вісім файлів PII-free,
усі `draft_unvalidated`). Валідатор — `lib/clinical-library.ts` (чиста функція
`auditLibrary`, без мережі/egress/БД/`./protocols`). Автоперевірка —
`tests/clinical-library.behavior.test.mjs` (12 тестів переобчислюють ці факти).

### Прямі підрахунки (переобчислено з файлів)

| Набір | Файл | К-сть |
|---|---|---|
| Нормальні/базові шаблони | `radiologyos-normal-templates.json` | **10** |
| Патологічні знахідки | `radiologyos-pathology-findings.json` | **31** |
| Клінічні правила (warn-only) | `radiologyos-clinical-rules.json` | **8** |
| Синтетичні приклади (**виключено**, не записи) | `radiologyos-template-examples.json` | 3 |

Маніфест (`radiologyos-protocol-library.json`) заявляє 10 шаблонів + 31 знахідку —
**збігається** з прямим підрахунком (`manifestMatches=true`). `source_summary`
зводить 1846 рядків вихідного XLSX у категорії — успадкована, клінічно **не**
валідована рубрикація (лишаємо як довідку про походження).

### Модальності та придатність

Погоджені модальності (AGENTS.md §46): КТ, рентгенографія, флюорографія,
пантомографія, УЗД. У кодуванні бібліотеки `CT` = КТ, `XR` =
рентгенографія/флюорографія — **погоджені**; `MRI` (МРТ) — **НЕ погоджено**.

| Модальність | Шаблони | Знахідки | Статус |
|---|---|---|---|
| CT | 7 | 31 | погоджена |
| XR | 2 | 0 | погоджена |
| MRI | 1 (`mri_brain_base`) | 0 | **needs_review** (поза AGENTS.md) |

**Жоден** із 41 запису не позначено `import_ready`: усі `draft_unvalidated`, тож
стеля придатності PR1 — `needs_review` (потрібна клінічна перевірка лікарем).
`mri_brain_base` додатково позначено `needs_review` як незгоджена модальність —
підключення МРТ у конструкторі є окремим наступним етапом і тут **не**
виконується. Відхилених (`rejected`) записів немає.

Зведення придатності: `import_ready=0`, `needs_review=41`, `rejected=0`.

### Перевірки цілісності (усі пройдено)

- **Унікальність ID** — унікальні в межах набору й між наборами
  (шаблони `*_normal`/`*_base`, знахідки `finding_001…031`); колізій немає.
- **Цілісність плейсхолдерів** — кожен `{param}` в описах/висновках знахідок
  має оголошений параметр; невизначених плейсхолдерів немає.
- **Одиниці виміру** — наявні лише `mm`, `HU`, `%`; усі числові параметри мають
  одиницю. Окремий параметр `morphology` у `finding_019` (дискове випинання)
  коректний (рядковий, без одиниці). `finding_013` (стеатоз) має HU печінки й
  селезінки окремими параметрами — норм.
- **Дані пацієнта** — незалежний скан усіх текстових полів (e-mail, телефон,
  довгі числові ID, іменовані пацієнти, дати народження) — **нічого не виявлено**;
  маніфест теж заявляє `patient_data_included=false`. `patientDataDetected=false`.

### Синтетичні приклади

`radiologyos-template-examples.json` — 3 фікстури (`example_001…003`), у т.ч.
крос-модальний приклад МРТ→КТ. Вони **не є записами бібліотеки** й не потрапляють
у жоден `verdict`; трактуються як тестові очікування для PR4 і **ніколи** не
імпортуються як реальні шаблони (межа 10).

### Клінічні правила

8 правил `warn_only`, `auto_rewrite=false`, `implementation_status=
specification_only_not_verified_against_PR661`. Сім збігаються з уже реалізованим
детермінованим контролером суперечностей (`lib/protocol-contradictions.ts`, MP3
E2): латералізація, жовчний міхур, асцит, рівень перелому, протрузія→грижа,
оклюзія на нативній КТ, мм/см. Восьме (`different_modality_visibility` — невидимість
на КТ знахідки попередньої МРТ ≠ регрес) збігається з рушієм порівняння
(`lib/protocol-comparison.ts`, MP3 E3). Звірку реалізацій із цими специфікаціями
віднесено до PR4 (Clinical Validation).

### Висновок Этапу 0

Бібліотека структурно цілісна, без даних пацієнтів, з унікальними ID і
коректними плейсхолдерами/одиницями. `safeForDryRun=true` — **це дозвіл лише на
майбутній dry-run адаптера/імпортера (PR2–PR3), НЕ на production-імпорт і НЕ на
публікацію.** Усі записи лишаються `needs_review` до клінічної перевірки.

## Журнал PR

- **PR1 — Library Audit (цей PR).** Бібліотеку (8 PII-free `draft_unvalidated`
  файлів) закомічено в `clinical-library/`; додано чистий валідатор/завантажувач
  `lib/clinical-library.ts` (`auditLibrary`, `scanForPatientData`,
  `extractPlaceholders`, `AGREED_MODALITY_CODES`) і
  `tests/clinical-library.behavior.test.mjs` (12 тестів переобчислюють прямі
  підрахунки й інваріанти). Без рантайм-змін застосунку, без міграцій, без
  торкання lifecycle/підпису/прав. Гейт зелений.

## Залишок (наступними PR)

- **PR2 — Import Adapter.** Чистий адаптер проміжний JSON → модель RadiologyOS
  (без нових таблиць, якщо не потрібні; з документованим rollback). Dry-run,
  валідація, детекція дублікатів, ідемпотентність, звіт create/update/skip/reject.
- **PR3 — Builder Integration.** Інтеграція в наявний конструктор (без дублю
  знахідок/порожніх абзаців/взаємовиключних авто-додавань). Без паралельного
  конструктора.
- **PR4 — Clinical Validation.** Звірка 8 правил зі специфікаціями; тести
  (зокрема 3 синтетичні приклади як очікування). Жодної публікації неперевірених
  шаблонів; стоп перед production-імпортом.
