# Telegram — вхідні заявки на запис (інтеграція)

Стартовий канал заявок — Telegram. Архітектура лишена розширюваною (телефон,
WhatsApp, email, Viber — поле `channel` у `intake_requests`), але **не заявляй,
що інші канали працюють, доки інтеграції реально не реалізовані**.

## Як це працює

1. Пацієнт пише боту вільний текст (напр. «хочу записатись на КТ»).
2. Вебхук `POST /api/telegram/webhook` перевіряє секрет заголовка
   `x-telegram-bot-api-secret-token` і резолвить організацію (fails closed —
   невідомий/дубльований секрет → `401`).
3. Якщо повідомлення — **не** команда (`/start <token>`, `/stop`) і не бот-команда,
   воно фіксується як **вхідна заявка** в `intake_requests` (ідемпотентно за
   `update_id` — повторна доставка не створює дубль). Боту відповідає чесний
   ack без медичних даних.
4. Реєстратор бачить заявку на сайті (роль `registrar`/`admin`), бере в роботу,
   створює/знаходить пацієнта й дослідження, звʼязує їх із заявкою і надсилає
   підтвердження назад у чат. Статус відправлення — **чесний** (якщо токен бота
   не налаштовано, система показує помилку, а не фальшиве «надіслано»).

Деталі моделі: `intake_requests` (`drizzle/0126_intake_requests.sql`) — `channel`,
`external_ref` (chat_id), `external_update_id` (ідемпотентність), `contact`,
`message`, `status` (`new`/`in_progress`/`converted`/`declined`),
`assigned_email`, `linked_booking_id`, `linked_patient_id`.

## Налаштування (секрети — у БД, не в коді)

RadiologyOS мультитенантний: секрети Telegram зберігаються **per-org** у таблиці
`organization_integration_settings`, а не у змінних середовища. Налаштовуються в
кабінеті **`/staff/settings`** (ролі з доступом до налаштувань):

| Ключ (`organization_integration_settings.key`) | Призначення |
|---|---|
| `telegram_bot_token` | токен бота від @BotFather (надсилання повідомлень/підтверджень) |
| `telegram_webhook_secret` | секрет, який Telegram надсилає у заголовку вебхука (перевірка автентичності) |
| `telegram_chat_id` | (за потреби) чат для сервісних сповіщень |
| `telegram_bot_username` | кеш імені бота для deep-link |

Кроки:
1. Створіть бота в @BotFather, отримайте **token**.
2. У `/staff/settings` збережіть `telegram_bot_token` і згенеруйте
   `telegram_webhook_secret`.
3. Зареєструйте вебхук Telegram на `https://<домен>/api/telegram/webhook` із тим
   самим `secret_token` (кнопка в налаштуваннях викликає Telegram API).
4. Перевірте тестовим повідомленням боту — заявка має зʼявитися в черзі.

**Ніколи не комітьте реальні токени.** Для розробки не надсилайте реальні
повідомлення й не використовуйте реальні дані пацієнтів.

## Приватність

- У підтвердженні боту — **мінімум** даних: час/статус запису, без діагнозу,
  зображень чи повного опису.
- Медичні результати доступні лише через захищений вхід у систему, не в чаті.

## Що ще заблоковано без облікових даних

- Фактичне надсилання підтверджень потребує збереженого `telegram_bot_token`
  конкретної організації; без нього API чесно повертає `sent:false` з причиною.
- Інші канали (phone/WhatsApp/email/Viber) — поле `channel` готове, самі
  інтеграції **не реалізовані** й не заявляються як робочі.
