# Конструктор протоколів `/staff/protocols` — аудит, архітектура, план

Документ веде роботу над MASTER-завданням «професійний конструктор
радіологічних протоколів». Він **маршрутизує й фіксує**, а не дублює канонічні
правила: архітектурна межа — в `AGENTS.md` і `docs/business-core.md`, lifecycle
протоколу — в `docs/workflows.md`, права — в `docs/roles-permissions.md`.

## Етап A. Аудит наявного стану (станом на цю гілку)

Головний висновок: **`/staff/protocols` — це вже зрілий структурований
конструктор, а не порожнє місце.** Повна відбудова з нуля порушила б і правило
завдання «не створюй дублікати / не переписуй працюючі модулі», і десяток
міграцій-тригерів, що гарантують незмінність підписаного клінічного змісту.
Тому роботу спрямовано на **реальні прогалини**, а не на переписування.

### Що вже є (не чіпаємо без потреби)

- **Двопанельний редактор** (`app/staff/protocols/page.tsx`): ліворуч — жива
  черга досліджень із фільтрами (очікують / до підпису / підписані / видані /
  усі), лічильниками, пошуком, тихим автооновленням кожні 45 с, deep-link
  `?open=`; праворуч — структурований редактор за шаблоном зі змістом,
  лічильником заповненості, захистом незбережених змін (`confirm` +
  `beforeunload`), друкованою формою (шапка госпіталю, блок пацієнта, підпис).
- **14 шаблонів у коді** (`lib/protocols.ts` `PROTOCOL_TEMPLATES`): КТ (ОГК,
  мозок, черевна порожнина, пазухи, хребет, урографія), рентген (ОГК, кістки,
  черевна порожнина, хребет, пазухи), флюорографія ОГК, універсальний. Кожен —
  типізовані секції/поля (line/text/select) з «нормальним» формулюванням.
- **Детермінований рендер тексту** `renderProtocolText` (спільний для друку,
  експорту, AI), «Заповнити норму», автопідбір шаблону за послугою.
- **Повний lifecycle** `draft → ready → signed → issued` з незмінністю на трьох
  рівнях (застосунок, DB-тригери 0043–0107, append-only `protocol_revisions`),
  **виправлення через addenda** (`/staff/protocols/corrections`, окремі
  незмінні документи з власним lifecycle), ролі (`canManageProtocols`=admin|
  radiologist; підпис — лише radiologist; видача реєстратором — metadata-only),
  tenant-scope, аудит кожної дії.
- **AI-чернетка** (`lib/ai.ts` + `/api/staff/ai/protocol-draft`): детермінована,
  офлайн, з обов'язковим дисклеймером, ніколи не підписує й не застосовує
  автоматично — лише пропонує «Вставити».
- **Широке тестове покриття** (понад десяток `tests/protocol-*`, `ai-draft`,
  `protocols-page-resilience`).

## Етап B. Архітектура доданого (цей PR)

Принцип: **медичний шар, адитивно, без зміни контрактів.** Протоколи за
`AGENTS.md` лишаються в medical domain і не стають господарськими сутностями;
їх append-only revision lifecycle недоторканний.

- **`lib/findings-composer.ts`** — чистий, типізований, без залежностей модуль:
  каталог знань (ділянка → орган → знахідка → латералізація/частка/сегмент →
  виміри → модифікатори) + `composeFinding(selection)`, що складає **українське
  речення опису і узгоджений висновок**. Приклад із §5 (S7–S10, −952 HU)
  відтворюється дослівно. Граматика забезпечена **передвідміненими формами**
  анатомії в каталозі (не морфологічний рушій) — чесно й коректно.
- **`insertComposedFinding(document, finding)`** — ДОДАЄ складений текст у вже
  наявні вільні поля `findings`/`conclusion` (append + дедуп), **ніколи не
  перезаписуючи** ручні правки лікаря (вимога §6). Документ незмінний (нова
  копія).
- **`reviewProtocol(input)`** — детерміновані клінічні перевірки §10 (конфлікт
  латералізації, норма у структурованому полі попри патологію, згадка динаміки
  без попереднього дослідження, характеристика без контрасту). Лише сигнали, не
  блокують збереження.
- **UI** — новий блок «Конструктор знахідок» у редакторі, **поза** lifecycle:
  гейтиться `canEdit` + змодельованою ділянкою, вставляє текст через
  `insertComposedFinding`, показує попередження. Жодного нового API, статусу,
  поля БД чи міграції; підпис/видача/незмінність недоторкані.

Покриття MVP-ділянок (Этап C завдання): **КТ ОГК** (легеня з часткою+сегментами,
плевра), **КТ головного мозку** (ішемія, крововилив, зміщення серединних
структур), **КТ органів черевної порожнини** (печінка, нирка, вільна рідина).

## Поетапний план

- **Етап A — аудит.** ✅ Цей документ.
- **Етап B — архітектура.** ✅ Цей документ + `lib/findings-composer.ts`.
- **Етап C — MVP конструктора.** ✅ Цей PR: композер + перевірки + UI-інтеграція
  для трьох КТ-ділянок, юніт- і UI-тести, без зміни lifecycle/API.
- **Етап D — розширення.**
  - **D1 (✅ зроблено).** Каталог розширено з 3 до 7 ділянок (додано КТ пазух, КТ

    нові знахідки в наявних КТ-ділянках; кожна знахідка отримала опційну
    **клінічну підказку** (`hint`, §4), показану в UI; `NORM_FIELD_MAP` розширено.
    Без міграцій, адитивно.
  - **D2 (✅ зроблено).** Жива панель прев'ю (§3): перемикач «Попередній
    перегляд» у редакторі показує рендер протоколу в реальному часі
    (`renderProtocolText`), read-only, прихований на друці, dark-theme. Без
    перебудови макета в три колонки (низький ризик), без міграцій.
  - **D3 (✅ зроблено).** Явні режими роботи (§6): Швидкий / Структурований /
    Вільний — перемикач угорі редактора. Режим — суто візуальна перевага;
    перемикання не стирає й не перезаписує поля (стан у `doc`). Без міграцій.
  - **D4a (✅ зроблено).** Синхронізація `docs/workflows.md` §6 з реальними
    статусами (`draft→ready→signed→issued`) + охоронець від дрейфу. Doc-only.
  - **D4b (✅ зроблено).** Умовні секції/поля (`showWhen`): поле/секція
    показується лише за умови на керівному полі. Враховано в render/sanitize/
    редакторі/друку; перше застосування — «Фаза контрастування» лише за
    внутрішньовенного контрастування. Без міграцій.
  - **D5a (✅ зроблено).** `method_ref` у `protocol_revisions` (міграція `0122`):

На цьому Этап D покриває §3–§7 завдання. Этап E (AI-функції понад наявну

- **Етап E — AI та інтеграції.** Диктування→структура, перевірка суперечностей,

  і без автопідпису.
- **Етап F — тестування.** Розширені функціональні/рольові/друк/відновлення
  чернеток; візуальна браузерна перевірка (нині заблокована — див.
  `docs/quality-audit.md`).

## Чесні обмеження цього PR

- Каталог знань — **курований seed** трьох ділянок, не вичерпний; UI показує
  лише змодельоване (для інших шаблонів лишається вільний текст). Розширення — D.
- Граматика тримається на передвідмінених формах у каталозі, а не на
  морфологічному аналізаторі: нові знахідки потребують ручного внесення форм.
- Перевірки `reviewProtocol` працюють зі **структурованих знахідок цієї сесії**
  (додані через конструктор) + тексту; вони дорадчі, не блокують збереження.
- **Візуальна браузерна перевірка не виконана** (authed `/staff/*` недоступний у
  середовищі) — технічна й функціональна перевірки пройдені кодом і тестами.
