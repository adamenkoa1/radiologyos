# CLAUDE.md — RadiologyOS

Інструкції для Claude Code / AI-агентів. Цей файл лише **маршрутизує** до
канонічних документів — не дублюй правила тут, щоб не було розбіжностей.

## Канонічні правила (читати перед будь-якою зміною)

- **`AGENTS.md`** — головні обов'язкові правила: архітектурна межа business-core,
  термінологія, ролі, модальності, стиль змін, що оновлювати після змін. Має
  найвищий пріоритет.
- **`docs/ui-ux-audit.md`** — playbook професійного UI/UX-аудиту сторінки
  (ролі, напрями аудиту, межі автономності, перевірка, оцінювання, звіт).
- Довідка: `docs/design-system.md`, `docs/styles.md`, `docs/components.md`,
  `docs/pages.md`, `docs/business-core.md`, `docs/domain-model.md`,
  `docs/roles-permissions.md`, `docs/workflows.md`, `docs/lessons.md`.

## Команди-скорочення

- **UI/UX-аудит сторінки:** «Проведи повний UI/UX-аудит цієї сторінки за
  правилами проєкту, внеси покращення та перевір результат.»
  → виконати процес із `docs/ui-ux-audit.md` для наданої сторінки (URL / маршрут
  / назва / скриншот / код): аудит → безпечні локальні покращення в межах
  дизайн-системи → перевірка (`tsc` / `lint` / `npm test`) → звіт з оцінкою
  «до/після». Зміни бізнес-логіки, API, маршрутів, прав доступу, платежів або
  глобальної дизайн-системи — лише після окремого погодження.

## Перевірка та доставка (стисло; деталі — в `AGENTS.md` і `docs/ui-ux-audit.md`)

- Гейт: `npx tsc --noEmit` → `npm run lint` (0 errors) → `npm test`.
- Одна функціональна задача — один PR; маленькі коміти; після змін оновити
  `docs/changelog.md` (і `docs/lessons.md` за потреби).
