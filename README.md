# RadiologyOS

Повноцінна система онлайн-запису відділення променевої діагностики Чернігівського військового госпіталю.

## Можливості

- публічний каталог із 38 послугами, цінами, внутрішніми кодами та відомими кодами eHealth;
- онлайн-запис для військових і цивільних пацієнтів;
- окремий розклад для КТ, цифрового рентгену та флюорографа;
- перевірка перетину записів з урахуванням тривалості процедури;
- блокування технічних вікон і простоїв обладнання;
- кабінет пацієнта для перевірки та скасування заявки;
- захищений кабінет персоналу зі статусами, перенесенням, нотатками та історією змін;
- призначення лікаря-рентгенолога та рентгенолаборанта на кожне дослідження;
- фіксація фактичного виконання, кількості анатомічних ділянок і номера зовнішнього документа;
- облік фактичних дат готовності й видачі протоколів із окремими правами лікаря;
- конструктор протоколів зі структурованими шаблонами за модальностями (КТ, рентген, флюорографія), автопідбором шаблону, типовими формулюваннями норми, версійністю, статусами «чернетка → готовий → виданий» та друком/PDF;
- CRM пацієнтів: єдина картка за номером телефону з історією візитів, протоколів та оплат, профілем (ПІБ, рік народження, теги, нотатки, «не турбувати»), журналом комунікацій і сегментами (повторні, майбутні візити, очікують протокол, борг оплати);
- внутрішній облік суми до сплати, фактичної оплати та перевірки НСЗУ;
- конструктор звітів із фільтрами, вибором колонок і п’ятьма готовими шаблонами;
- справжній Excel-експорт без ПІБ і телефонів пацієнтів та журнал усіх експортів;
- ролі адміністратора, реєстратора, лікаря-рентгенолога й рентгенолаборанта;
- керування доступом працівників без зміни коду;
- серверна валідація, нормалізація українських номерів і обмеження частоти запитів.

## Архітектура

- Next.js 16 і React 19;
- Vinext та Cloudflare Workers;
- Cloudflare D1;
- Drizzle ORM і версійовані SQL-міграції;
- Sign in with ChatGPT для ідентифікації персоналу.

Публічний сайт, запис, база заявок і кабінет персоналу працюють як одна система та використовують одну базу D1.

## Локальний запуск

Потрібен Node.js `>=22.13.0`.

```bash
npm run install:ci
npm run dev
```

Корисні команди:

```bash
npm run lint
npm run build
npm test
npm run db:generate
```

## База даних

Схема описана у `db/schema.ts`, а послідовні зміни зберігаються в `drizzle/`.
Початкова міграція створює заявки, а наступні додають предметну та операційну модель RadiologyOS:

- апарати та тривалість процедур;
- категорію пацієнта й тип направлення;
- нормалізований телефон;
- журнал подій і службові нотатки;
- персонал та ролі;
- технічні блокування обладнання;
- таблицю обмеження частоти запитів.
- протоколи досліджень;
- статуси оплати, фактичну сплачену суму та НСЗУ;
- призначених виконавців і фактичний час виконання;
- кількість анатомічних ділянок і номер зовнішнього документа;
- фактичні дати готовності та видачі протоколу;
- індекси для звітності за виконанням, обладнанням і виконавцями;
- журнал експорту звітів.

Серверні API не створюють таблиці під час звичайних запитів.

## Доступ персоналу

Перший адміністратор додається початковою міграцією. Після входу він керує іншими працівниками на сторінці `/staff`. Ідентифікація через Sign in with ChatGPT не замінює авторизацію: кожен email додатково перевіряється в таблиці `staff_members`.

Розподіл прав:

| Роль | Заявки й виконавці | Виконання | Протоколи | Оплата / НСЗУ | Звіти й Excel | Персонал | Простої |
|---|---|---|---|---|---|---|---|
| Адміністратор | керування | фіксація | керування | керування | перегляд і експорт | керування | керування |
| Реєстратор | керування | фіксація | перегляд | керування | перегляд і експорт | ні | перегляд |
| Лікар-рентгенолог | перегляд | фіксація | керування | перегляд | перегляд і експорт | ні | перегляд |
| Рентгенолаборант | перегляд | фіксація | перегляд | перегляд | перегляд і експорт | ні | перегляд |

Готові шаблони звітів: реєстр досліджень, контроль протоколів, навантаження персоналу, навантаження обладнання та фінансовий реєстр. Період звіту визначається фактичною датою виконання, а для ще не виконаних записів — запланованою датою. ПІБ і телефони в Excel не включаються, але деталізовані реєстри містять дані про медичні послуги й мають зберігатися та передаватися лише захищеними каналами.

## Захист даних

Система зберігає лише дані, необхідні для організації запису. Перед робочим використанням власник системи має:

- затвердити правову підставу й строк зберігання даних;
- перевірити вимоги установи до розміщення медичних даних у Cloudflare D1;
- обмежити доступ до проєкту та регулярно переглядати список персоналу;
- затвердити порядок резервного копіювання, видалення та реагування на інциденти.

Наявні поля оплати й НСЗУ є внутрішнім операційним обліком персоналу. Вони не списують кошти та не надсилають дані до ЕСОЗ. Інтеграції з оплатою, НСЗУ або зовнішньою МІС підключаються лише після вибору офіційного провайдера, договору та погодженої специфікації API.
